{{版本要求|2.1.0}}
灰机作为主要面向游戏的维基，背后隐藏的其实是大量的游戏数据与计算逻辑，传统的MediaWiki功能远不能满足制作游戏信息页面的需要，为此灰机先后上线了[[帮助:Semantic_MediaWiki|SMW]]、[[帮助:MongoDB支持|MongoDB]]、[[帮助:SMongo|SMongo]]、[[帮助:模块|Lua]]以及[[帮助:Python|Python]]等等黑科技，以帮助机长们更愉快地搞<del>基</del>机。

然而这些黑科技大多是增强了后端数据库的功能，对于前端界面的呈现爱莫能助。由于安全以及风格一致等的考虑，MediaWiki在内容格式的控制上极为严格，大多数有用的HTML标签无法使用，JavaScript解析只支持ES3标准。虽然灰机有可以自定义页面[[帮助:Mustache模板|模板]]以及将JavaScript[[帮助:零件|模块化]]的功能，但是依然不能做到随心所欲。

如何真正解放自我？答案是来用React。本篇教程将教你如何在你的站点中页面中放置React制作的界面。虽然本教程是面向React，但实际上对于其他的UI框架如Vue或者Angular等也是同样的道理，可以举一反三。

== 实现原理 ==
开发一个Node.js项目，并使用Web打包工具将其打包成单独的js文件，借助于灰机的Gadget零件等功能将其上传至灰机站点并运行。

== 前置条件 ==
你在默认权限下是不能向灰机上传代码的，需要[[帮助:用户权限#开发者权限|开发者权限]]。

React开发其实是一种专业技能，是可以拿来找份工作养家糊口的，所以是有一定的学习成本和难度的。至少你应该是懂得一定编程概念的人，并熟悉JavaScript的开发。

=== 我需要使用React吗 ===
并不是任何维基站都适合使用React，我们推荐将React用于'''具有复杂界面的工具'''这种定义的内容上。如果你只是普通的维基页面或者展示游戏数据的页面，灰机目前提供的工具已经可以完全满足你的需要。

以下是一些适合使用React的例子：

* 游戏的互动地图
* 游戏数据库的搜索界面
* 各种游戏数据的模拟工具，如天赋模拟器，配装模拟器
* 具有复杂逻辑的页面呈现，如界面的布局随着用户的不同选择区别迥异

使用React会使得你呈现的内容无法被搜索引擎索引，从而导致你的维基不会出现在搜索引擎列表当中，因而请在设计时考虑SEO优化的部分。

== 开发环境 ==
使用React能够使你将数量庞大的React社群开源项目引入到你的站点中，极大地增强你的站点的功能并提高开发效率。但也要时刻注意所引用的库的数量问题，过多的库会使得你最终的打包文件大小高达数M，会大幅降低你的页面的载入速度，甚至无法正常使用。

对于每个项目使用什么样的库是你个人的选择，不在本文的讨论范围之内，但下面几个组件基本是开发所有项目都需要用到的。

=== Visual Studio Code ===
'''Visual Studio Code'''（简称VSCode）是微软开发的开源IDE，短小精悍，完美支持TS和JS开发，且完全免费。除非你有更习惯更顺手的IDE，否则VSCode会是你的开发最佳选择。

下载：https://aka.ms/win32-x64-user-stable

=== Node.js ===
'''Node.js'''（或叫Node）是一个命令行下的JavaScript运行环境，就是这个东西将JS的应用范围从浏览器带到了服务器，就是这个东西让JS焕发了第二春。而我们需要它来运行编译以及打包工具。同时Node会附带一个包管理程序npm，其他的工具都需要使用npm来安装。

官网：https://nodejs.org/

下载：https://nodejs.org/zh-cn/download/

=== React ===
'''React'''是我们的主角，是Facebook制作的一款UI框架。借助React可以在浏览器中以直观的方式制作动态变化的Web界面。React的开发包含了众多的设计模式、应用规范以及性能技巧，这些已经完全超出了本文要讨论的范围。同时，本文也不会深入讲解如何使用React开发，请自行查阅相关的资料。从React入门到熟练开发可能需要一段时间，不要放弃呀。

官网：https://reactjs.org/

=== TypeScript ===
'''TypeScript'''（简称TS）是微软出品的一种语言，是JavaScript的一个超集。TypeScript的主要目的是给JavaScript增加类型检查的功能，以减少像JS这样动态类型的脚本语言因人为的原因出错的可能。同时如果你有支持TS的IDE，那么还会获得代码自动完成的功能。

但是我们使用TS的主要原因，是因为MW的文本解析引擎无法识别ES3规范之外的JS代码，而当今的JS代码都是基于ES6规范，最低也是ES5。现在的年代去写ES3，简直是开历史的倒车！而TS的编译器，可以把TS代码编译为ES3（或者ES5，或者ES6）。做这个事情最有名的工具叫Babel，但是TS的配置更为简单，并且还能免费获得类型检查的功能，更何况React对TS有良好的支持，何乐而不为呢？

官网：https://www.typescriptlang.org/

=== Browserify ===
'''Browserify'''是一个将多个JavaScript模块打包成单个JS文件的工具。作为一个现代的开发语言，模块化的文件组织结构是良好架构设计落地的基础。不过模块化只有在Node环境下支持，浏览器内是不支持加载模块的（相关的标准已经成型，部分浏览器新版本已经支持），为了让浏览器能正常运行我们模块化的代码，我们需要Browserify来将所有模块放入单个文件内，一次性地让浏览器载入。虽然Webpack是这方面的王者，有着更为完善的功能和社群支持，但是我们本着够用就好简单是王道的原则选择了Browserify。

官网：http://browserify.org/
