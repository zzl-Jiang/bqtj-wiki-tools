本篇帮助文档将介绍HuijiAgent所使用的知识库模块。
'''知识库'''是灰机wiki配合[[help:AI支持框架|AI支持框架]]，所提供的一个面向子站点机长和管理员暴露的功能接口，用以生成托管站点图谱和缓存。它主要用于HuijiAgent的知识查询功能、基于站点内容的辅助作业以及驱动面向一般读者的'''站点助手'''（见后文《站点助手》）。

*知识库由托管站点的机长/管理员通过驾驶室开启和配置
*知识库会采集和更新托管站点中的内容，构建AI可以快速检索和理解的知识体系，而不是传统意义上的爬取和搜索，可以极大的提高AI对站点内容的理解精确度。


==知识库的功能==
我们以目前已采集的数据（站点：r6s，分类：特勤干员）为例。

打开[[club:special:cockpit#/agentv2/chat|灰机Agent]]，创建一个会话。

向其发起询问，例如'''介绍一下彩虹六号的干员Maverick'''。

此时，agent会先确定你要找的信息位于站点r6s中（由siteMgr维护），然后在知识库中进行查询：
<pre>
我先确认彩虹六号围攻在灰机上的站点前缀。
> 在siteMgr中判断站点，确定是r6s
> 在知识库中以"Maverick", "Maverick 干员", "裂石"搜索r6s集合
> 得到若干片段，并确定词条名为Maverick，搜索该词条的导言、干员配置、背景故事章节
> 根据需要再额外获取其他章节
> 收集到足够信息，开始回答
**Maverick（烈马）**是《彩虹六号：围攻》中的一名进攻方干员，2018 年 Y3S3「暗空行动」登场。玩家常称他"小马哥""电焊"。
...
</pre>

如果在知识库中没有相应条目，Agent会转为使用维基搜索（即special:search），虽然更方便但是燃料消耗巨大，因为返回的是“整页渲染内容”。

关于Agent具体是怎么使用这些工具的，建议你直接问它。


===由页面制作切片===
访问[[club:special:cockpit#/tools/chunktest|切片测试工具]]页可进行切片预览。

在那页右边能看到四步：'''抓取 → 前端预清洗 → 转 Markdown → 切片'''，用「上一步 / 下一步」翻（一次只显示一步）。

最后那步（切片）里章节默认'''全部展开'''，列表右上角可以一键“全部收起”（大文档想先看目录的话用它）。

这页只有该站点的机长 / 管理员（或灰机职员）能用，而且页面必须是 wikitext。

还是以Maverick这一页举例，原始页面为133KB，预处理后58KB，转Markdown后仅剩13KB。

在进行段落拆分后，单个片段将进一步缩小，从而实现节约燃料的目的。

==入库==
在入库之前，请先进行一波判断。以下将极大提高Agent的检索效率。

最重要的部分是，“这个页面适合agent读吗”？我让agent采集了这个页面是希望他回答什么问题？

然后，依次检查以下事项：
*导言部分（第一个标题之前的部分）
*infobox：有更好。
*分类：有更好。
*标题层级关系：很重要。

而对于数据生成的、大部分信息是布局网格类的页面，则不适合使用现阶段的知识库。请参考后文“备选方案”一节。

===入库清洗规则===
以下元素会在预清洗环节被移除或转换：
*navbox（移除）
*html注释（移除）
*references（数据化）
*cite (简化，并和references对应)
*toc（目录，数据化）
*infobox（转换为表格）
*内联display:none的元素（移除）
*图片和缩略图（简化）
*红链（指向还没创建的页面）：退化为纯文本，并标注“（未创建）”。
*站内链接：'''保留链接'''，地址按标题重建成 wiki 页地址；跨页面的锚点（#某节）也一起保留。
*跨站 / 站外 / 图片链接：保留原地址。
*只在同一页里的锚点（#开头）：退化为纯文本（读者就在这一页，目录在手）。
*排版用元素（b,i,strong,em，释放）
*class为kb-ignore的元素（移除）
**因此你可以给不想被采集的元素加上这个类。

==开通知识库==
站点的'''机长'''或'''管理员'''可自行开通本站的知识库，'''灰机职员'''可以给任意站点开启知识库。

开通入口：驾驶室侧栏 → '''知识库''' → [[club:special:cockpit#/kb/@home|知识库首页]] → 「创建知识库」，然后根据指引操作：

#'''使用须知'''：确保了解知识库的原理并对内容质量负责。
#'''选择站点'''：填写需要创建知识库的站点前缀。
#'''采集范围'''：通过页面分类确定进入知识库的页面范围，详见[[#采集范围]]。这一条可以先跳过，建好之后再回项目页加。
#'''站点助手'''：设置站点助手的头像、系统提示词等信息，详见[[#站点助手]]。
#'''开始采集'''：点「保存配置并开始采集」，开始建库。

新任命的机长或管理员可能由于缓存，暂时没有获取到权限而被拒。可等待一小时后再次尝试。

===采集范围===
知识库通过页面分类设定采集范围。
每个采集范围需要设置入口分类、必须包含的分类和排除分类，即包含所有同时包含入口分类、必须包含的分类，同时不包含排除分类的页面。
不同采集范围之间为合取关系，即一个页面只要满足一条采集范围，就会进入知识库最终采集范围。（即使这个页面可能满足其他采集范围的排除分类）。

除了按分类划范围，还有另一种取列表的方式：'''全命名空间（ns0）'''，给分类体系很松的站用，详见[[#全命名空间（ns0）]]。

'''一条范围都不加也能建库'''：新库可以先建好、之后再回项目页划范围（但在那之前知识库里不会有任何页面）。

'''改完的范围不会自己开始采'''：保存之后，到概览页点一次「全量缓存更新」（把全部范围重新枚举一遍）才会生效。

加 / 减辅助分类、排除分类这种'''改判据'''的操作，不会自动删掉已经采进来的页面 —— 它们会变成「可能不在范围里」，概览页会排出一句「N 个页面需要重新核对」。

两种处理方式：

*'''先点一次「全量缓存更新」'''：凡是被当前范围枚举到的页，系统会顺手把它的「依据」换成现在这套范围（不用额外请求），大部分黄点会自己消掉。
*'''剩下的再点「核对」'''：只有枚举不到的那些（真的掉出范围了）才需要逐条回站点上问一遍 —— 还符合的刷新记录，不符合的删掉；站点没答上来的（网络问题）一律不动。

编辑范围的弹窗里可以直接'''预览命中效果'''：填好分类点「看看会命中哪些页」，就能看到这次会收进来多少页。

====全命名空间（ns0）====
如果本站的分类体系很松（大量页面根本没挂分类），按分类划范围会大面积漏采。这时可以用「'''全命名空间'''」范围：直接从主命名空间走一遍，不依赖分类。

'''它怎么筛'''：
*只枚举主命名空间，'''不含重定向页'''。
*页面至少要有一个'''非隐藏分类'''（一个分类都没有的自制模板、测试页、空页不收）。这是它唯一的质量筛。

'''在哪儿开'''：
*知识库项目首页 → 「采集范围」卡片里有一张「'''全命名空间（ns0）'''」的卡，上面那个开关就是它。
*能不能用这个开关由'''站点级白名单'''决定，只有灰机官方（staff）能开 —— 就是同一张卡下方那颗「'''授权该站点采集 ns0'''」。没授权时开关是灰的，旁边会写「这个站还没被授权」。需要就找 staff 申请。
*开关打开 = 加上这条范围；关闭 = 删掉这条范围（'''不会'''删掉已经采进来的条目）。

'''打开之后要再点一次「全量缓存更新」'''，才会按这条范围开始枚举。

'''注意'''：
*关掉开关（或删掉这条范围）之后，只属于它的那些缓存会在下次「全量缓存更新」时清掉，凌晨那一趟也会继续清。
*它'''不参与'''「采集范围预览」—— 预览是按分类枚举的，ns0 没有分类可填。
*本站开了 ns0 之后，凌晨那趟的「清除已不属于任何范围的条目」会'''跳过'''：ns0 收的就是分类很松甚至没分类的页面，用分类去判会误删。
*它和分类范围是'''并列'''的：任意一条命中就入库，可以两个一起用。

===知识库更新===
知识库开通后会立刻开始采集，并每日自动更新。从页面右下角知识库按钮可查看所在页面是否在采集范围、当前采集版本、下次自动更新时间。

====自动更新====
每天北京时间凌晨3点，系统会自动跑一趟，一共三件事：

#'''接着采'''：上一个批次被每日额度截断的那部分继续采。
#'''跟进改动'''：拉取站点的'''近期改动'''（recentchanges），自动重新命中采集范围的页面入库：
#*新页面 / 内容改动 / 页面移动：自动重采并更新切片。'''回退'''（rollback）也算一次修改。
#*页面被删除：清除知识库中的内容。
#*分类被修改，不再命中采集范围：清除知识库中的内容。
#'''清除已不属于任何范围的条目'''：用入库时存下来的分类判断，不发站点请求。每站每晚最多清 5000 条，没清完第二天继续。开了「全命名空间」的站这一步会跳过。

====手动更新====
前往驾驶室可手动更新知识库。

*'''采集指定页面'''：知识库项目页 →「'''页面'''」页签 → 选中指定页面 → 点击「重新采这一页」。
*'''采集指定分类'''：鼠标移到知识库项目首页「采集范围」卡片里某一条范围上，右上角会出现三颗按钮，最左边那颗 ↻ 就是「按这个分类采一遍」。
*'''全量更新'''：概览页「采集范围」卡片上方那颗「'''全量缓存更新'''」—— 把全部范围重新枚举一遍。加了新范围之后要跑它。

手动更新需要时间，更新任务将进入队列。

===落库队列===
托管站点采集任务会提交到一个队列管理系统，与所有站点的采集任务排队进行。队列按来源分优先级，从高到低：

#按采集范围批量（机长点的「开始 / 继续采集」）
#单页重采（驾驶室里「重新采这一页」）
#按分类采（采集范围卡片上那颗 ↻）
#站点上报的页面事件 / 每天凌晨的自动跟进

*所以有时候会出现别人触发的任务“插队”，请耐心等待。
*刚入过库的页面再点，只会告诉你「已是最新」——不会重复抓。
*限额：单批最多3万条，每个站每天最多3万条，整个队列最多压5万条（到顶了会提示先等它消化）。
*任务失败会自己退避重试（最多3次）；试满仍失败的，联系staff在后台重跑。

===采集状态与日志===
知识库项目页（'''概览'''）顶部有五格数字：
*'''已缓存页面'''
*'''最近一次采集'''
*'''下次自动采集'''（倒计时）
*'''今天的采集额度'''（每天 0 点恢复）
*'''队列状态'''：分四档，见下

队列状态四档：
*'''采集中'''：正在采本站的页面，或者本站的任务已经排到队头。
*'''排队中'''：本站有任务在等，但前面还有别的站的任务。
*'''他站任务中'''：队列在给别人干活，本站没有排队的任务（随时可以点按钮）。
*'''空闲'''：队列是空的。

每一次动作（自动更新、全量更新、按范围更新、核对、编辑范围、改站点助手的配置 / 头像）都会记一条'''日志'''，在项目页的「日志」页签里能看到：谁点的（系统发起的显示「系统」）、什么时候、结果如何。

==站点助手==
创建了知识库的站点可以使用'''站点助手'''（SiteAgent）功能，即本站点的AI角色。站点页面的右下角停靠区会多一个机器人按钮，可以进入AI大语言模型驱动的聊天框。与你在各种场景经常遇到的AI助手类似，它可以快速的回答基于本托管站点的问题，起到辅助检索的作用，这个功能主要面向一般读者。

[[File:QQ截图20261016130925.jpg|center|link=|400px]][[File:QQ截图20261016130935.jpg|center|link=|400px]]
站点助手与[[club:special:cockpit#/agentv2/chat|灰机Agent]]的区别：

*站点助手面向托管站点的'''读者'''：他只专注于理解、记忆本站点的内容，由本站点的知识库所驱动，同时检索本站的实时页面。它不会修改任何页面。查不到东西时它会被要求如实说“不知道”，不允许编造站点没有的内容。
*托管站点的机长和管理员可以通过知识库配置站点助手的'''性格、语气、身份知识储备'''。
*站点助手实际运行时所消耗的大模型成本通过灰机的捐赠和加油机制补充运作。
**灰机用户等级大于等于2级的用户均具有一定的免费额度（根据用户等级可能会有不同）
**用户等级为1级的用户（即完成了注册的无编辑记录的纯内容消费用户）使用站点助手需要保证账号中有剩余的燃料值（具体开销取决于大模型提供商，如DeepSeek的收费标准）'''燃料从使用者自己的余额里扣'''。
**燃料分配：当站点捐赠达到一个最低可以运行的额度后，机长可以分配站点燃料池中的一定数量的余额，向未登录匿名用户开启站点助手的查询功能（暂未开放），余额用尽后，面向匿名用户的站点助手查询功能会暂时关闭，直到有新的燃料被分配。

===个性化定制===
站点可以根据自身的需要和特点为站点助手配置个性化的名字、头像、口径、引导语。需要'''机长 / 管理员'''，或者'''灰机职员'''权限。

入口是知识库项目页的「'''站点助手'''」页签（页签栏第二个，上面直接画着它的头像和名字）。这一页'''所有人都能看''' —— 谁都能知道这个站的助手叫什么、口径写了什么；不能改的人看到的是置灰的表单。

*'''名字'''：显示在它每条回答头上（最长 24 字）。缺省为「站点助手」。
*'''头像'''：正方形、256×256 的 png。
*'''口径 / 性格'''：写进 systemPrompt。例如「本站是《彩虹六号》设定站，回答时优先用游戏内术语的官方中文译名」。
*'''引导语'''：只在的新会话里显示一行字（例如「问我这个站的条目、设定或做法都行」）。引导语仅作为给用户的提示，不会发送给大模型。

===提示词范例===
通过提示词可以改变站点助手的「性格」：

*提示词会'''拼在通用口径后面'''，所以覆盖通用的站点助手人格。通用部分已经定义了「本站优先查知识库 / 不知道就说不知道 / 说人话」，以及灰机是什么、markdown 该怎么写、工具怎么用、来源怎么标 —— '''不要在提示词里重复这些'''，重复只会把真正属于本站的那几句稀释掉。
*系统会自动添加两块内容：'''【你自己】'''（就是上面「名字」那一项）和'''【跟你说话的人】'''（对方的用户名、他在本站的权限组）。所以也不用写「你叫某某」「先看他是不是管理员」。
*提示词是'''纯文本'''拼进去的：没有变量、没有占位符，也引用不了知识库内容；一最多 4000 字。

一般来说推荐约定如下四类内容：

#'''身份和语气'''：让谁扮演谁、用什么口吻、怎么称呼读者。
#'''本站的行文约定'''：术语用哪一套、专有名字怎么写、怎么给读者指路。
#'''该去哪儿查'''：本站的哪类内容在哪几节，什么情况该去读实时页面。
#'''边界'''：你不希望它干的事（剧透、评价现实政治、给「怎么绕过编辑限制」这类答案）。

以'''r6s'''站为例，我们想让它的助手扮演干员'''钉锁（Gridlock）'''，可以这么写：

<pre>
你是「钉锁」（Gridlock），本名 Tori Fairous，澳大利亚空降特勤团（SASR）的干员，
现在同时担任 r6s.huijiwiki.com 的站点助手。

语气：像刚从前线下来跟同事闲聊。直爽、爱拿农场和修拖拉机打比方，偶尔抱怨杂事太多，
但一聊到战术和装备就很认真。不要客服腔，不要自称「AI 助手」，不要在开头写「当然可以」「好问题」。
称呼读者用「伙计」。

本站口径：
- 干员、枪械、地图都用本站词条里的写法，别把国服和国际服两套名字混着写；
- 提到干员时先给正式名，需要时补上常用称呼（例：钉锁（Gridlock），外号「地刺」「大妈」）；
- 伤害、射速、生命值这类数值只能来自本站词条——不确定就去查，别凭记忆报数；
- 问「怎么打 / 怎么克制某个干员」，先看那条目的「游戏策略」「战术特性」几节。

边界：
- 本站没有的内容（比如还没上线的赛季）就说没查到；
- 不聊现实世界的政治、不评价真实国家与军队（游戏里那些虚构阵营可以聊）；
- 有人问怎么绕过编辑限制、怎么刷编辑数，直接说不知道。
</pre>

这四段分别约束一件事：第一段告诉它'''是谁、在哪儿、对着谁说话'''；「语气」那段全是'''可执行的小规则'''（「不要自称 AI」「用『伙计』」比「要自然一点」有用得多）；「本站口径」是'''只有这个站才需要'''的约定；「边界」就是一句句的命令。

几条经验：

*'''素材就在本站词条里'''：钉锁爱拿农场打比方、被博士评价为「有天生的领导力却拒绝晋升」、和 Mozzie 是老搭档 —— 这些都写在「背景故事」那几节里。给它一两个只属于它的习惯（口头禅、爱打的比方、对某个队友的态度）比堆一堆形容词更「入戏」。
*'''写完就试'''：项目页右上角「问问 Ta」问两句，或者直接到那个站上点右下角的机器人按钮。不满意回来改，'''下一轮就生效'''，不用等什么。
*'''字数不是越多越好'''：这段每轮都要带上，也吃燃料。宁可写 5 条能落地的规则，也别写 20 条正确的废话。
*'''别忘了改名字'''：名字填成「钉锁」，别人问「你是谁」它才会照这个答（名字每轮会单独注入一句，界面上显示的也是它）。

==数据类页面的备选方案==
我们在前文提到过：
#class包含kb-ignore的元素会被移除；
#style包含display:none的元素也会被移除。

因此，对于数据类页面，可以使用以下方案：
*给不想给agent看的页面主结构加上kb-ignore
*生成页面时额外生成一个可阅读段落，并且让他不可见。
**由于上述第二条规则，你需要单独写一个class让他display:none，否则仍会被处理函数忽略。
